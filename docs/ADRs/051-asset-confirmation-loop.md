# ADR-051: 资产确认闭环（统一资产清单 + 撤销 + 渲染级门禁固化）

## 状态
Accepted (v0.6.4) — 2026-09-07 docker 单机人工验收通过 + 66 项渲染级自检全绿
后转正。k8s 侧为**假数据验证**（开发环境无集群），未做 k8s E2E 真机验收，
诚实标注待后续补验。

## 背景
bp_v06x v0.6.4 = 「**前端资产确认闭环**」。v0.6.3（ADR-050）已在后端建立
资产状态机与三段留痕，但前端未接入：

- 资产页**分裂成两张表**（k8s pod 表 / docker 容器表），「分级 / 资产状态 /
  操作」三列模板逐字重复，用户感受不到"同一套资产模型"
- docker 容器**没有详情弹窗**、列表行没有 `row-click`、点击无反应
- 确认后**无法再次修改**，admin 二次覆盖无入口
- 一次决策写多条留痕（`human_decision` + `status_transition`×N）**平铺展示**，
  看起来像被操作了多次
- **筛选只作用于拓扑，下方清单纹丝不动**
- 分级文案用 **严重/高危/中危/低危**——那是漏洞危害等级（CVSS），
  与"资产业务重要性"语义混淆

## 方案

### 统一资产清单（核心）
新增 `unifiedAssets` computed：把 k8s pod 与 docker 容器**归一化成同构对象**，
差异字段留空。UI 只需一套列模板：

```
类型 | 名称 | 命名空间/节点 | 镜像 | 状态 | IP 地址 | 服务 | Labels | 特权 | 分级 | 资产状态 | 操作
```

- **类型列**（Pod / 容器）区分数据来源——两者是同一类资产（可发现/可确认/
  可覆盖/可查留痕），只是来源不同
- docker 侧补齐原本缺失的维度：`created` / `ip`（`NetworkSettings.IPAddress`
  及各网络回退）/ `labels`（含 compose 元数据）
- 派生收益：**v0.6.7 六层审计接入时只需改一处**

### 筛选语义修正
- **多选并列**（OR 语义）：分级/镜像/命名空间/节点均为数组，可「核心 + 重要」
- **暂存 + 应用**：下拉绑 `draftFilter`，点「应用筛选」才提交到 `topoFilter`
  并重绘——多选下每勾一项就重绘会让拓扑反复跳动
- **移除资产状态筛选**：待确认已有顶部横幅 + 详情入口直达；「已覆盖」本就是
  「已确认 + 人工改级别」的一种，三者不是并列维度
- **移除「显示本地容器」开关** → docker 归入 `docker` **伪命名空间**。
  docker 容器只能来自被监控的这台机器，不存在"其他机器的 docker"
- 分级文案改为 **核心/重要/一般/边缘**；数据值仍为 `critical/high/medium/low`
  （与 `config/assets.yaml` 及存量 `logs/assets.yaml` 兼容，无需迁移）

### 撤销（防误操作）
- `AssetStore.revert()` — `CONFIRMED|OVERRIDDEN → PENDING_REVIEW`，
  资产重回待确认队列并恢复闪烁提示
- **级别不回滚**：人工覆盖过的级别是有价值信息，盲目退回 auto 会丢失人工判断。
  撤销只回退"确认状态"这一件事
- 权限 = **admin**（与 override 一致）：撤销是"推翻已生效决策"，不放开给 operator
- 原因必填，留痕仍走 `event_id` 分组

### 留痕按事件聚合
`AssetStore._audit(event_id=)`：一次 confirm 的 2 条 / override 的 3 条**共用
同一 id**；前端 `auditGroups` 聚合成「决策卡片」（主条目 + 缩进的侧面），
存量无 `event_id` 数据按 `ts+type` 兜底。

### 渲染级门禁固化（决策 #51 落地）
新增 `scripts/panel_render_check.js` + `make panel-check`：
1. `node --check` 语法门禁
2. **逐页模板编译**：遍历 `pages` 注册表对 9 个组件 `createApp().mount()`
3. **行为级断言**：假数据 + ECharts 桩，断言容器入图 / 待确认标记 /
   筛选并集 / 详情弹窗字段完整性
4. k8s 侧用假数据独立挂载验证（无集群时的次优解）

## 后果
- ✅ 资产页从两张表合一，模板重复消除，k8s/docker 行为一致
- ✅ 误操作可撤销，且撤销本身留痕（审计闭环完整）
- ✅ 决策 #51 从"口头纪律"变为可执行门禁（66 项）
- ❌ k8s 侧未真机验收（开发环境无集群），仅假数据验证归一化逻辑成立
- 📝 `docker` 伪命名空间为硬编码常量 `DOCKER_NS`，若未来出现同名 k8s
  命名空间会撞车（概率极低，届时改带前缀即可）
- 📝 jsdom 装在 `/tmp`（dev-only），未污染 `requirements.txt` / CI
