# ADR-000: 将内部决策记录转为公开 ADR 文档

## 状态
Accepted (v0.4.1, 2026-08-14)

## 背景
项目开发全程维护一份内部决策文档（本地文件，含真实姓名，标记"不上传任何 GitHub 仓库"）。外部评估（DeepSeek 模型对话）指出：这份记录是项目最大的差异化资产——ADR（Architecture Decision Record）是 ThoughtWorks 技术雷达推荐实践（AWS / Microsoft / Kubernetes KEP 均采用），公开后企业用户能看到工程成熟度、开源贡献者能理解设计约束、答辩评委能看到科研方法的严谨性，是对抗"toy 质疑"的证据链。

## 验证过程
- 与外部评估（DeepSeek）对话确认 ADR 的行业标准与面试价值
- 逐条扫描本地记录：33 条决策 + 附录 A 4 条，结构统一（问题来源 → 怎么触发 → 建议方案 → 最终选择），与 ADR 的 背景/验证过程/备选方案/决策/后果 天然对应
- 隐私审计：真实姓名仅出现在文件尾脚注，路径含用户名一处，脱敏成本低

## 备选方案
- **方案 A**：保持本地，不上传（现状）——决策记录是"隐藏资产"，面试只能口头描述
- **方案 B**：脱敏后转为公开 docs/ADRs/（一决策一篇），本地保留原始——公开 + 可追溯
- **方案 C**：全量 38 篇一次迁移——工作量大且边际收益递减

## 决策
选择方案 B，但**精选 7 篇先行**（003/006/014/024/032/033 + 本决策），其余 31 条保留在本地原始记录，答辩前分批迁移。**编号方案**：NNN = 本地决策序号，全局唯一稳定——将来补传按序号插入，无需重命名已有文件；本决策为"第零号"（ADR-000），ADR-001~033 对应本地决策 #1~33，ADR-034~037 预留附录 A1~A4，ADR-038+ 留给将来本地新增决策。

## 后果
- ✅ 面试/答辩谈资（"37+ 个决策 + 元决策"）；开源贡献者可追溯设计约束；匿名化后无隐私风险
- ❌ 脱敏维护成本（每条过一遍隐私）；与本地文档双轨同步
- 📝 决策文档本身的元决策——决策体系自举

- ADR-037（隐私与工具痕迹，预留）：脱敏规范的来源
