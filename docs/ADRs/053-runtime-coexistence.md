# ADR-053: 资产清单运行时共存 + 运行时筛选

## 状态
Accepted (v0.6.5.2) — 2026-09-17 真机联调通过（guard sudo+BPF 与面板同时运行，
`/api/assets` 实测返回 k8s 9 pod + docker 4 容器；门禁 71/71、单测 186）。

## 背景
v0.6.4（ADR-051）的前端统一资产清单已能把 pod 与容器归一化成同一张表，但
后端 `/api/assets` 仍是**二选一**：`_k8s_client_v1()` 可读就只返回 k8s pod，
否则才走 docker 容器。开发机同时存在 k3s（`learning-ebpf`）与 rootless docker
时，资产页只能看到 pod，本机容器完全不可见 —— 要看到容器只能改 `HOME` 让
kubeconfig 加载失败来"骗"过运行时判定（调试期的临时手段，不能作为产品行为）。

根因是运行时被当成**部署形态**（DaemonSet=k8s / 单机=docker）而非**数据来源**：
在实际的混合节点上两者可以同时存在，面板没有理由只显示其中一种。

## 决策
- **后端两路独立采集、合并返回**：k8s 与 docker 各自 try/except，成功则把
  结果并入同一响应（`nodes`/`services` 来自 k8s，`containers` 来自 docker），
  并新增 `runtimes: ['k8s','docker']` 与合并后的 `total`；单路失败只追加到
  `error`，**不影响另一路**。
- **前端运行时筛选**：资产页筛选栏新增「运行时」多选（`k8s Pod` /
  `Docker 容器`），默认空 = 全显示；筛选谓词**同时用于拓扑图与资产清单**，
  避免两处各筛各的（v0.6.4 的教训：筛选只作用拓扑、列表纹丝不动）。
- **计数与标注**：顶部显示 `k8s N · Docker M`，两者都有时标注「同机共存」。
- **向后兼容**：只新增字段（`runtimes`、docker 条目的 `asset_id`），不删除
  既有字段，旧前端仍可读 `nodes`/`containers`。

## 备选方案
- **保留二选一 + 手动切换开关**：仍把运行时当互斥部署形态，用户在混合节点上
  必须来回切换才能看全，且"当前看到的是哪一半"要靠记忆。
- **前端发两次请求合并**：`/api/assets?runtime=k8s` + `?runtime=docker`。
  接口更"RESTful"，但首屏要等两个独立往返、失败语义分散在客户端，且已有
  的 `total/services` 聚合口径会被拆散。后端合并在服务端一次收敛更简单。

## 后果
- ✅ 混合节点上 pod 与容器同时可见，无需环境 trick
- ✅ 单路故障隔离（k8s API 挂了仍能看到本机容器，反之亦然）
- ✅ 拓扑 / 清单 / 计数共用一套运行时谓词，不会出现"图里没了、表里还在"
- ❌ 资产页每次刷新要打两次外部依赖（k8s API + docker socket），首屏延迟略增
- 📝 "服务暴露"表仍只来自 k8s（docker 无 Service 概念，保持为空）
- 📝 docker 侧仍只列**运行中**容器（`containers.list()` 默认）；已退出容器
  是否纳入资产清单留待后续（与生命周期语义相关，不在本决策范围）
